# Тестовое задание: Real-time Chat Application

## Описание

Разработать веб-приложение для обмена сообщениями в реальном времени. Опционально можно добавить функционал видео-историй (stories).

## Технологический стек

- **Backend:** NestJS + TypeScript
- **Frontend:** SvelteKit + TypeScript
- **Database:** MongoDB
- **Real-time:** Socket.io / WebSocket

## Функциональные требования

### Авторизация

- Регистрация пользователя (email, password, username)
- Вход в систему (JWT токены)
- Защита приватных роутов

### Диалоги (обязательно)

- Список всех диалогов пользователя
- Создание нового диалога с другим пользователем
- Отправка текстовых сообщений
- Получение сообщений в реальном времени (WebSocket)

### Пользователи

- Список всех пользователей системы
- Поиск пользователей по username
- Возможность начать диалог с любым пользователем

### Stories (опционально, будет плюсом)

- Запись видео через веб-камеру (до 15 секунд)
- Лента историй — список пользователей с активными stories
- Автоудаление — stories удаляются через 24 часа

## Технические требования

### Backend (NestJS)

- REST API для основных операций (auth, users, conversations, messages)
- WebSocket gateway для real-time сообщений
- JWT авторизация
- Валидация входящих данных
- Базовая обработка ошибок
- Опционально: API для stories, загрузка видео (multipart/form-data)

### Frontend (SvelteKit)

- Svelte stores для состояния (auth, messages, conversations)
- WebSocket клиент для real-time сообщений
- Обработка loading и error states
- Опционально: Запись видео (MediaRecorder API), видео плеер, таймер записи

## Что НЕ требуется

- Групповые чаты (только 1-на-1 диалоги)
- Отправка файлов/изображений в чат
- Редактирование/удаление сообщений
- Фильтры и эффекты для видео
- Обработка/конвертация видео на бэкенде
- Push-уведомления
- Развертывание в продакшн
- Сложная UI/UX (достаточно базового функционала)
- Оптимизация размера видео (можно загружать как есть)

## Ожидаемый результат

- Репозиторий на GitHub с исходным кодом
- README с инструкциями по запуску
- Docker Compose для локального развертывания (опционально, но будет плюсом)
- Работающее приложение, которое можно запустить локально

## Критерии успеха

### Обязательно

- Приложение запускается и работает
- Можно зарегистрироваться и войти в систему
- Можно обмениваться сообщениями в реальном времени
- Сообщения приходят через WebSocket без перезагрузки страницы
- Код структурирован и читаем
- Базовая обработка ошибок присутствует

### Будет плюсом

- Реализован функционал stories (запись, просмотр, автоудаление)
- Docker Compose для быстрого запуска
- Тесты (хотя бы базовые)
