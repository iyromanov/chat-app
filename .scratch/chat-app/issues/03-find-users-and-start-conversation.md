# 03: Поиск собеседника и создание диалога

**What to build:** пользователь находит другого участника, начинает личную переписку и видит один общий пустой диалог у обоих участников без перезагрузки.

**Blocked by:** 02 — Вход, выход и жизненный цикл JWT.

**Status:** ready-for-agent

**Spec:** [Согласованная спецификация](../spec.md).

**User stories:** 13–27 в части поиска, создания, списка и доступа к диалогам; 60–61.

- [x] Список показывает остальных пользователей без их email. Пустой запрос показывает список, поиск по подстроке username не учитывает регистр и выполняется сервером по всем пользователям; нет совпадений — отдельное пустое состояние.
- [x] Пользователи сортируются по нормализованному username и ID. Infinite scroll загружает порции по 50 через items/nextCursor; курсоры валидируются и привязаны к параметрам поиска. Смена поиска сбрасывает страницы, устаревший ответ не подменяет актуальную выдачу.
- [x] Нажатие “Start conversation” создаёт или возвращает диалог двух разных пользователей; с собой начать нельзя. Mongoose-схема Conversation и уникальный ключ неупорядоченной пары предотвращают дубликаты, включая конкурентное создание обоими участниками.
- [x] Созданный диалог сразу отображается у обоих участников с username собеседника и подписью “No messages”. Повторное действие открывает существующий диалог.
- [x] API списка возвращает только диалоги текущего пользователя. Для пустых диалогов сортировка — по времени создания и ID, от новых к старым; infinite scroll использует порции по 50 и курсоры.
- [x] Событие о новом диалоге доставляется всем подключённым вкладкам участников и не доставляется посторонним. Ответ HTTP и событие объединяются в один элемент списка.
- [x] Backend проверяет права через прикладной сервис владельца диалога; чужие модели не импортируются напрямую. Контракты запросов, ответов, ошибок и событий добавлены в общий пакет; HTTP-операции отражены в OpenAPI и клиентских типах.
- [x] FSD-срезы поиска и начала диалога используют HTTP-клиент; данные диалогов принадлежат entity-store, события связываются с обновлением в app. Экраны работают на узкой ширине, показывают загрузку, ошибки и пустые состояния.
- [x] HTTP-тесты с Testcontainers проверяют поиск, исключение себя, отсутствие email, страницы, некорректные курсоры, повторное и конкурентное создание, запрет диалога с собой и изоляцию списков. Socket.io-тесты проверяют доставку нового диалога участникам и отсутствие доставки третьему пользователю.
- [x] Вручную проверен путь двух пользователей от поиска до одного общего диалога, включая дополнительные вкладки и infinite scroll; инструкция демонстрации добавлена в README.
