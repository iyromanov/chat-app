# 06: Запись и публикация видеоистории

**What to build:** пользователь записывает короткое видео, просматривает и переснимает его, публикует и открывает свою сохранённую историю через защищённый API.

**Blocked by:** 02 — Вход, выход и жизненный цикл JWT.

**Status:** ready-for-agent

**Spec:** [Согласованная спецификация](../spec.md).

**User stories:** 40–46, 50; 57 в части API-доступа; 60–63.

**Priority:** низкий; выполнять после завершения ядра чата (01–05). Это порядок приоритетов, а не дополнительная техническая зависимость.

- [ ] Авторизованный пользователь в Chrome записывает видео через MediaRecorder с камеры; видит таймер, запись автоматически останавливается через 15 секунд. До публикации доступны предварительный просмотр и пересъёмка.
- [ ] При доступном микрофоне запись содержит звук. При недоступном микрофоне возможна запись без звука с предупреждением; недоступная камера и неподдерживаемая запись показывают понятную ошибку и не блокируют работу чата.
- [ ] Публикация выполняется через multipart/form-data с валидацией и лимитом 25 МБ; UI показывает загрузку, успех и ошибки. Формат поддерживается проверяемым браузером; конвертация и оптимизация не вводятся.
- [ ] Story содержит автора, сведения о файле, публикацию и истечение через 24 часа. Видео сохраняется на диске API в постоянном Docker volume; один автор может иметь несколько активных историй.
- [ ] Публикация сохраняет файл перед записью метаданных. При ошибке MongoDB файл удаляется по возможности, информация об ошибке обрабатывается; история не показывается опубликованной без подтверждения. Незавершённые загрузки не доступны как истории.
- [ ] Автор может открыть опубликованное видео и проверить результат. Видео выдаётся через приватный API с проверкой JWT и срока, не через общедоступный каталог. Через 24 часа API отказывает в доступе даже без фоновой очистки.
- [ ] Обычный перезапуск контейнеров сохраняет видео и метаданные. Volume, конфигурация хранилища и режим публикации описаны в README.
- [ ] NestJS-модуль stories владеет схемой Story и файловой логикой; FSD-срез публикации использует общие контракты и клиент. Multipart и видеоответы явно описаны в OpenAPI; генерация и клиент корректно поддерживают этот путь.
- [ ] HTTP-тесты с Testcontainers проверяют авторизацию публикации/выдачи, допустимую загрузку, превышение лимита, несколько историй и запрет видео после срока с управляемым временем. Камера и MediaRecorder проверяются вручную, а не считаются покрытыми backend-тестами.
- [ ] В Chrome вручную проверены звук, режим без микрофона, отказ камеры, таймер, пересъёмка, публикация и воспроизведение; UI пригоден для узкого экрана.
