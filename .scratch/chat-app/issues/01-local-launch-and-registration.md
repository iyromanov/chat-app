# 01: Локальный запуск и регистрация

**What to build:** проверяющий запускает приложение локально, регистрирует пользователя и попадает в приватную область. Это первый работающий путь от формы через API до MongoDB, с воспроизводимой проверкой.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

**Spec:** [Согласованная спецификация](../spec.md).

**User stories:** 1–4, 12; 60–65 в части запуска, регистрации и основы проверок.

- [x] Один pnpm workspace содержит web на SvelteKit и API на NestJS с TypeScript, единым lockfile и корневыми командами разработки и проверок. Docker Compose запускает приложение и MongoDB; в браузере используется один адрес localhost для web и API.
- [x] README описывает минимальный запуск, обязательные параметры, пример окружения и требования к Docker. Конфигурация проверяется при запуске; обычный перезапуск контейнеров сохраняет данные MongoDB.
- [x] Адаптивная форма регистрации на английском языке использует Flowbite Svelte/Tailwind, показывает загрузку и ошибки. После успешной регистрации открывается приватная область; проверка авторизации имеет отдельное состояние загрузки.
- [x] Email обязателен и проверяется на формат; username — 3–30 латинских букв, цифр или подчёркиваний; пароль — 4–128 символов без дополнительных требований к составу. Пароль сохраняется стойким хешем и не возвращается клиенту.
- [x] Mongoose-схема User сохраняет отображаемый username и нормализованные email/username. Уникальные индексы предотвращают регистрацию дубликатов без учёта регистра, включая конкурентные запросы; конфликт превращается в понятную ошибку.
- [x] Регистрация выдаёт JWT на 24 часа в постоянной HttpOnly cookie без автоматического продления. Авторизация stateless, без коллекции Session и denylist. Приватная операция получения текущего пользователя защищена guard.
- [x] Frontend восстанавливает авторизацию через API в браузере, без SSR приватных данных и общего серверного пользовательского store. FSD задаёт публичные интерфейсы и направление импортов; слои создаются по необходимости, готовые UI-компоненты не содержат предметной логики.
- [x] Общий framework-независимый пакет содержит Zod-контракты регистрации, текущего пользователя и ошибок. NestJS DTO и pipes используют эти схемы; ошибки содержат code, message и при необходимости ошибки полей, без внутренних данных.
- [x] NestJS экспортирует OpenAPI и Swagger UI для реализованных операций. Из документа генерируются типы openapi-typescript; форма обращается через фабрику openapi-fetch в shared, настроенную на cookie и обработку ошибок. Workspace содержит команды генерации и проверки актуальности.
- [x] Настроены ESLint, Prettier и проверки TypeScript/Svelte, включая правила импортов FSD и изоляцию пакета контрактов. Настроен заменяемый источник времени backend для последующих проверок сроков.
- [x] HTTP-тесты Jest с MongoDB в Testcontainers проверяют успешную регистрацию, валидацию, регистронезависимую уникальность, конкурентный конфликт и отказ приватного API без JWT. Форму и локальный запуск проверяют вручную; README содержит команды тестов.


## Comments

### 2026-10-14 — реализация завершена

- Созданы pnpm workspace, SvelteKit web, NestJS API, общий пакет Zod-контрактов и Docker Compose с постоянным MongoDB volume и единым адресом `http://localhost:8080`.
- Реализованы регистрация, scrypt-хеширование, нормализованные уникальные индексы, JWT на 24 часа в HttpOnly cookie, защищённый `GET /api/auth/me`, браузерное восстановление авторизации и адаптивная форма.
- OpenAPI и HTTP-типы генерируются; `pnpm check` проверяет TypeScript/Svelte, ESLint/FSD, форматирование и актуальность генерации. Добавлены заменяемые часы backend.
- Проверки: `pnpm check`, `pnpm build`, `pnpm test` (14 HTTP-тестов Jest с MongoDB в Testcontainers), `docker compose up --build -d`. Проверено отклонение запуска без обязательной конфигурации и отклонение запрещённых импортов ESLint.
- В Chrome проверены регистрация, ошибки полей и конфликт email без учёта регистра, состояние отправки на медленной сети, восстановление после перезагрузки, независимая сессия и ширина 375 px без горизонтальной прокрутки. SSR содержит загрузку, а не приватные данные.
- После `docker compose restart` прежняя cookie открывает сохранённого пользователя. В MongoDB проверены оба уникальных индекса, сохранение отображаемого username и scrypt-хеша без plaintext-пароля.
- README содержит минимальный запуск, параметры окружения, команды разработки/проверок и ручную приёмку. Вход/выход и дальнейший жизненный цикл относятся к задаче 02.
