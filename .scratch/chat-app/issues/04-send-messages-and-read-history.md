# 04: Отправка сообщений и сохранённая история

**What to build:** участники обмениваются текстом без перезагрузки, видят сохранённую историю и актуальный список диалогов; повтор отправки не создаёт второго сообщения, посторонние не получают доступ.

**Blocked by:** 03 — Поиск собеседника и создание диалога.

**Status:** ready-for-agent

**Spec:** [Согласованная спецификация](../spec.md).

**User stories:** 23–24, 26–34, 38–39 в части отправки и объединения данных; 60–61.

- [x] Сообщение отправляется через REST. После удаления пробелов по краям текст содержит 1–2000 символов; пустой и слишком длинный текст отвергается, внутренние переносы строк сохраняются. UI показывает понятную ошибку.
- [x] Message — отдельный документ MongoDB с диалогом, отправителем, временем, текстом и идентификатором попытки. Уникальный индекс по диалогу/отправителю/попытке защищает от повторных и конкурентных вставок.
- [x] Повтор той же попытки с тем же нормализованным текстом возвращает существующее сообщение; другой текст возвращает контрактную ошибку конфликта. Новый идентификатор означает новую отправку.
- [x] Сервер сохраняет сообщение до рассылки через Socket.io. Ответ REST и событие содержат одинаковое публичное представление сообщения; все вкладки обоих участников получают его, посторонние — нет.
- [x] Клиент объединяет HTTP-ответы и события по ID без дубликатов и не объявляет успех до подтверждения сохранения. Отправитель видит сообщение также в других вкладках.
- [x] При открытии загружаются последние 50 сообщений, на экране — от старых к новым. «Load more» добавляет старые порции без пропусков и дубликатов; порядок по времени и ID однозначен при одинаковом времени.
- [x] История сохраняется после перезагрузки и повторного входа. API и прикладной сервис проверяют участие перед чтением и отправкой; знание чужого ID не даёт доступа.
- [x] Список диалогов показывает последнее сообщение и время, сортируется по последней активности и ID; для пустого диалога использует время создания. Последнее сообщение вычисляется из Message индексированной агрегацией, без копии в Conversation и без многодокументной транзакции.
- [x] Новое сообщение обновляет и переставляет диалог во всех подключённых вкладках. Entity-срезы не импортируют друг друга для этого обновления; связывание события выполняет app. Сочетание страниц списка и событий не создаёт дубликатов.
- [x] Контракты и OpenAPI/HTTP-типы обновлены. HTTP-тесты с Testcontainers проверяют текст, историю, страницы, одинаковое время, сортировку, повторные и конкурентные попытки, конфликт текста и запрет доступа посторонним. Socket.io-тесты проверяют сохранённое содержимое и доставку только участникам.
- [x] Вручную проверены переписка двух пользователей без перезагрузки, дополнительные вкладки, загрузка старой истории и узкий экран; README дополнен сценарием.


## Comments

### 2026-10-15 — реализация готова к ручной приёмке и ревью

- Ветка реализации: `codex/messages-history-implementation`, основана на интеграционной `codex/send-messages-history`. Реализованы отдельные Message-документы с уникальностью попытки, нормализация и конфликт текста, сохранение перед доставкой всем вкладкам участников, авторизованная история с курсорами по времени/ID, индексированная агрегация последней активности диалогов.
- Frontend: entity-store сообщений, feature отправки, widget переписки и связывание независимых stores в app. События и HTTP объединяются по ID; устаревший ответ списка не заменяет более новое последнее сообщение. Неуспешная отправка сохраняет попытку при повторе неизменённого текста, новый текст получает новый ID. После уничтожения composer его HTTP-ответ не обновляет состояние другого входа.
- TDD на согласованных HTTP/Socket.io-границах с Testcontainers: первая отправка дала 404 до реализации; конкурентная попытка возвращала 8 ID до уникального индекса; Socket.io-тест завершался таймаутом до рассылки; активность диалога сортировалась неверно до агрегации. После соответствующих срезов тесты прошли.
- `pnpm test` — 47 тестов, включая 6 новых сценариев сообщений; `pnpm check` — TypeScript/Svelte, ESLint/FSD, Prettier и актуальность OpenAPI/клиента; `pnpm build` — успешно. Сборка сообщает известные предупреждения аннотаций стороннего Zod, без ошибок.
- README дополнен сценарием двух пользователей, дополнительных вкладок, проверки 2000 символов, подгрузки истории и узкого экрана. Ручная браузерная приёмка и итоговое ревью ещё не выполнены этим исполнителем; последний критерий намеренно остаётся открытым.
- Полное восстановление пропущенных новых сообщений, все необходимые порции и состояние соединения относятся к задаче 05 и здесь не объявляются завершёнными. Статус сохранён по существующим значениям локального трекера; окончательное завершение фиксируется чеклистом и комментарием после приёмки.
