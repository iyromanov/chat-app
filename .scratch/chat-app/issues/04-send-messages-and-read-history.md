# 04: Отправка сообщений и сохранённая история

**What to build:** участники обмениваются текстом без перезагрузки, видят сохранённую историю и актуальный список диалогов; повтор отправки не создаёт второго сообщения, посторонние не получают доступ.

**Blocked by:** 03 — Поиск собеседника и создание диалога.

**Status:** ready-for-agent

**Spec:** [Согласованная спецификация](../spec.md).

**User stories:** 23–24, 26–34, 38–39 в части отправки и объединения данных; 60–61.

- [ ] Сообщение отправляется через REST. После удаления пробелов по краям текст содержит 1–2000 символов; пустой и слишком длинный текст отвергается, внутренние переносы строк сохраняются. UI показывает понятную ошибку.
- [ ] Message — отдельный документ MongoDB с диалогом, отправителем, временем, текстом и идентификатором попытки. Уникальный индекс по диалогу/отправителю/попытке защищает от повторных и конкурентных вставок.
- [ ] Повтор той же попытки с тем же нормализованным текстом возвращает существующее сообщение; другой текст возвращает контрактную ошибку конфликта. Новый идентификатор означает новую отправку.
- [ ] Сервер сохраняет сообщение до рассылки через Socket.io. Ответ REST и событие содержат одинаковое публичное представление сообщения; все вкладки обоих участников получают его, посторонние — нет.
- [ ] Клиент объединяет HTTP-ответы и события по ID без дубликатов и не объявляет успех до подтверждения сохранения. Отправитель видит сообщение также в других вкладках.
- [ ] При открытии загружаются последние 50 сообщений, на экране — от старых к новым. «Load more» добавляет старые порции без пропусков и дубликатов; порядок по времени и ID однозначен при одинаковом времени.
- [ ] История сохраняется после перезагрузки и повторного входа. API и прикладной сервис проверяют участие перед чтением и отправкой; знание чужого ID не даёт доступа.
- [ ] Список диалогов показывает последнее сообщение и время, сортируется по последней активности и ID; для пустого диалога использует время создания. Последнее сообщение вычисляется из Message индексированной агрегацией, без копии в Conversation и без многодокументной транзакции.
- [ ] Новое сообщение обновляет и переставляет диалог во всех подключённых вкладках. Entity-срезы не импортируют друг друга для этого обновления; связывание события выполняет app. Сочетание страниц списка и событий не создаёт дубликатов.
- [ ] Контракты и OpenAPI/HTTP-типы обновлены. HTTP-тесты с Testcontainers проверяют текст, историю, страницы, одинаковое время, сортировку, повторные и конкурентные попытки, конфликт текста и запрет доступа посторонним. Socket.io-тесты проверяют сохранённое содержимое и доставку только участникам.
- [ ] Вручную проверены переписка двух пользователей без перезагрузки, дополнительные вкладки, загрузка старой истории и узкий экран; README дополнен сценарием.
