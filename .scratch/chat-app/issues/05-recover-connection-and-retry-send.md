# 05: Восстановление после сбоев соединения и отправки

**What to build:** пользователь видит состояние соединения, получает пропущенную переписку после обрыва и безопасно повторяет отправку с неопределённым результатом.

**Blocked by:** 04 — Отправка сообщений и сохранённая история.

**Status:** ready-for-agent

**Spec:** [Согласованная спецификация](../spec.md).

**User stories:** 35–39; 26, 31, 34 в части восстановления; 60–61.

- [x] UI показывает состояние Socket.io-соединения, отличает неопределённый результат отправки от подтверждённого и позволяет повторить попытку с прежним идентификатором и текстом.
- [x] Повтор не создаёт второе сообщение, в том числе когда исходный запрос был сохранён, но HTTP-ответ потерян. Новые сообщения во время офлайна не ставятся в автоматическую очередь отправки.
- [x] Первоначальная загрузка, переподключение и возвращение на вкладку синхронизируют историю и список диалогов через REST. MongoDB остаётся источником истины.
- [x] API поддерживает курсорную загрузку пропущенных новых сообщений. Если пропущено больше 50, клиент загружает все необходимые порции, а не только последнюю страницу.
- [x] События во время начального запроса и восстановления объединяются с REST-данными по ID; сообщение на границе загрузки не теряется и не отображается дважды. Аналогично объединяются данные списка диалогов.
- [x] Перестановка диалога во время прокрутки не создаёт дубликат; клиент учитывает изменение активности и при синхронизации обновляет данные. Полный снимок списка на время прокрутки не вводится.
- [x] После выхода или истечения JWT восстановление не возобновляет приватные действия и не возвращает очищенные данные предыдущего входа. На вкладку остаётся не более одного соединения.
- [x] При сбое между сохранением и рассылкой сообщение остаётся в MongoDB и появляется при следующей синхронизации. Долговечная очередь, transactional outbox и обещание гарантированной немедленной доставки не добавляются.
- [x] HTTP/Socket.io-тесты с Testcontainers проверяют доступность сообщений, отправленных без соединения получателя, получение более одной порции, безопасный повтор и восстановление после переподключения. Наблюдаемые результаты проверяются на публичных интерфейсах.
- [x] Вручную проверены потеря сети, потеря ответа отправки, события во время загрузки, несколько вкладок, возвращение на вкладку, выход и истечение во время восстановления. README описывает сценарии и ограничение доставки до следующей синхронизации.

- API поддерживает защищённые курсоры новых сообщений `after=<messageId|start>` и все последующие порции. Клиент при восстановлении сверяет последние страницы до старейшего ранее загруженного REST-сообщения, объединяет события по ID и обновляет курсор старой истории. Это восстанавливает длинные пропуски и поздние записи внутри загруженного участка; более старая история доступна через Load more. Первоначальная загрузка остаётся последними 50 сообщениями.
- Показано состояние соединения; неопределённая отправка имеет явный повтор неизменяемой исходной попытки. Редактирование черновика не меняет её ID и текст. Сохранённые API-ответы, события и история подтверждают попытку; автоматическая очередь отправки не добавлена.

Регрессионный клиентский HTTP/Socket.io-тест затем воспроизвёл пропуск поздно появившегося сообщения за уже сдвинутой границей. Оба исправлены. `pnpm test`: 48 API-тестов с MongoDB Testcontainers и 16 клиентских тестов. `pnpm check` и `pnpm build` прошли. Добавлена отсутствовавшая команда `generate:check`, необходимая существующему полному check.
- Независимое ревью стандартов: замечаний нет. Ревью требований: одна гонка позднего сохранения исправлена в `9777af7`; повторное ревью обеих осей — без замечаний.
- Браузерная приёмка выполнена в Chromium через Chrome DevTools на локальном Compose, в независимых сессиях localhost/127.0.0.1 и дополнительных вкладках. Проверены потеря сети, состояния Disconnected/Connected, восстановление 105 сообщений тремя страницами без дублей, обновление превью и доставка дополнительных сообщений во вкладки. На окончательной сборке начальная история содержала 50 сообщений, после ещё 105 отправок при отключённой сети — 155 уникальных сообщений, включая все 105 новых.
- В браузере проверены изменение черновика после неопределённой отправки и повтор с прежними ID/текстом; отдельно потеря HTTP-ответа после фактического сохранения при заблокированных событиях и синхронизации: явный повтор дал ровно одну сохранённую запись. После восстановления события также подтверждают сохранение без дубля.

Выход при двух задержанных ответах очистил обе вкладки текущей сессии; их освобождение не вернуло приватные данные, независимая сессия сохранилась. Клиентское истечение проверено сокращённым X-Auth-Expires-At при задержанном REST-ответе; реальное серверное истечение JWT дополнительно покрывают тесты с управляемым временем.
