# 05: Восстановление после сбоев соединения и отправки

**What to build:** пользователь видит состояние соединения, получает пропущенную переписку после обрыва и безопасно повторяет отправку с неопределённым результатом.

**Blocked by:** 04 — Отправка сообщений и сохранённая история.

**Status:** ready-for-agent

**Spec:** [Согласованная спецификация](../spec.md).

**User stories:** 35–39; 26, 31, 34 в части восстановления; 60–61.

- [ ] UI показывает состояние Socket.io-соединения, отличает неопределённый результат отправки от подтверждённого и позволяет повторить попытку с прежним идентификатором и текстом.
- [ ] Повтор не создаёт второе сообщение, в том числе когда исходный запрос был сохранён, но HTTP-ответ потерян. Новые сообщения во время офлайна не ставятся в автоматическую очередь отправки.
- [ ] Первоначальная загрузка, переподключение и возвращение на вкладку синхронизируют историю и список диалогов через REST. MongoDB остаётся источником истины.
- [ ] API поддерживает курсорную загрузку пропущенных новых сообщений. Если пропущено больше 50, клиент загружает все необходимые порции, а не только последнюю страницу.
- [ ] События во время начального запроса и восстановления объединяются с REST-данными по ID; сообщение на границе загрузки не теряется и не отображается дважды. Аналогично объединяются данные списка диалогов.
- [ ] Перестановка диалога во время прокрутки не создаёт дубликат; клиент учитывает изменение активности и при синхронизации обновляет данные. Полный снимок списка на время прокрутки не вводится.
- [ ] После выхода или истечения JWT восстановление не возобновляет приватные действия и не возвращает очищенные данные предыдущего входа. На вкладку остаётся не более одного соединения.
- [ ] При сбое между сохранением и рассылкой сообщение остаётся в MongoDB и появляется при следующей синхронизации. Долговечная очередь, transactional outbox и обещание гарантированной немедленной доставки не добавляются.
- [ ] HTTP/Socket.io-тесты с Testcontainers проверяют доступность сообщений, отправленных без соединения получателя, получение более одной порции, безопасный повтор и восстановление после переподключения. Наблюдаемые результаты проверяются на публичных интерфейсах.
- [ ] Вручную проверены потеря сети, потеря ответа отправки, события во время загрузки, несколько вкладок, возвращение на вкладку, выход и истечение во время восстановления. README описывает сценарии и ограничение доставки до следующей синхронизации.
