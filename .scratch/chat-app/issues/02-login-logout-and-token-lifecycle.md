# 02: Вход, выход и жизненный цикл JWT

**What to build:** пользователь возвращается в приложение по email и паролю, сохраняет вход в браузере, выходит во всех вкладках текущего входа и теряет доступ после истечения JWT. Независимый вход другого браузера сохраняется.

**Blocked by:** 01 — Локальный запуск и регистрация.

**Status:** ready-for-agent

**Spec:** [Согласованная спецификация](../spec.md).

**User stories:** 5–12; 60–61 в части авторизации.

- [ ] Форма входа принимает email и пароль, использует общий типизированный HTTP-клиент и показывает загрузку и понятные ошибки неверных данных. После входа открывается приватная область; перезагрузка и закрытие браузера сохраняют вход до истечения JWT.
- [ ] Guards проверяют подпись и срок JWT без обращения к хранилищу сессий. Приватные HTTP-операции не допускают запросы без действительного JWT; регистрация и вход явно публичные.
- [ ] Аутентификация использует `@nestjs/passport`: `passport-local` для входа по email и паролю, `passport-jwt` для проверки JWT из HttpOnly cookie и guards на основе `AuthGuard`. JWT выпускается через `@nestjs/jwt`. Уже реализованная JWT-защита приведена к этому подходу с сохранением проверки истечения с управляемым временем.
- [ ] Собственный код ограничен регистрацией и поиском пользователя, вызовом библиотеки хеширования и проверки пароля, настройкой cookie, интеграцией проверки с Socket.io и управлением сроком соединений; библиотечные механизмы аутентификации не дублируются. Проверки участия в диалоге остаются в прикладных сервисах.
- [ ] JWT хранится в HttpOnly cookie и действует 24 часа без автоматического продления. Новая авторизация не требует серверной Session; ранее выданный JWT не отзывается при выходе.
- [ ] В браузере создаётся одно Socket.io-соединение на вкладку после восстановления авторизации. Handshake проверяет JWT; входящие обработчики, если они есть, также защищены.
- [ ] Выход очищает cookie, авторизацию и предметные stores всех вкладок текущего браузера, отключает соединения текущего входа и показывает вход. Независимый вход того же пользователя в другом браузере продолжает работать.
- [ ] Скопированный JWT после выхода остаётся действительным до срока истечения, включая новое Socket.io-подключение; это ограничение явно описано в README. Отключение текущих соединений не выдаётся за отзыв токена.
- [ ] Истечение JWT прекращает доступ HTTP и уже существующего Socket.io-соединения, а не только запрещает новое подключение. Клиент прекращает приватные действия и показывает вход.
- [ ] Авторизацией и жизненным циклом соединения владеет app. Shared сообщает об ошибке авторизации через интерфейс клиента без импорта auth-store; stores и соединения не разделяются между пользователями на сервере.
- [ ] Контракты, OpenAPI и сгенерированные типы обновлены. Jest-проверки через HTTP и Socket.io покрывают успешный/неуспешный вход, handshake, выход, независимость другого входа, действительность копии JWT после выхода и истечение с управляемым временем.
- [ ] Вручную проверены восстановление входа, приватный маршрут, очистка состояния нескольких вкладок и сохранение независимого входа в другом браузере.
