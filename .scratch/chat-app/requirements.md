# Уточнение требований

Статус: функциональные и [технические требования](technical-decisions.md) согласованы, итог подтверждён пользователем. Это журнал договорённостей для подготовки итоговой спецификации. Более поздние уточнения заменяют ранние варианты там, где они различаются.

Итоговая спецификация опубликована в [spec.md](spec.md). Для декомпозиции и реализации использовать её; этот документ сохраняет историю уточнений.

Источник: [INITIAL_REQUIREMENTS.md](../../INITIAL_REQUIREMENTS.md).

## Согласовано — раунд 1

- Целевой бюджет выполнения: 12 часов, с допустимым небольшим превышением согласно раунду 6.
- Обязательное ядро чата реализуется первым.
- Stories входят в объём, имеют самый низкий приоритет и реализуются в конце.
- Docker Compose и базовые автоматические тесты входят в план сдачи.
- Для каждой пары разных пользователей существует ровно один диалог, в том числе при одновременном создании обоими участниками.
- Повторное начало переписки открывает существующий диалог. Диалог с собой исключён.
- Сообщения сохраняются; история доступна после перезагрузки, повторного входа и возвращения пользователя, который был офлайн.
- Простой интерфейс на английском языке, пригодный для компьютера и телефона, без отдельного дизайн-макета.
- Экраны: регистрация, вход, список диалогов, поиск пользователей, переписка; также интерфейс stories согласно исходному заданию.
- Предусматриваются пустые состояния, загрузка и понятные ошибки.
- Индикаторы набора текста, присутствия онлайн и прочтения исключены из объёма.

## Согласовано — раунд 2

- Email и username уникальны без учёта регистра. Username отображается с выбранным пользователем написанием.
- Вход по email и паролю. Смена username, восстановление пароля и подтверждение email исключены из объёма.
- Вход сохраняется после перезагрузки и закрытия браузера до истечения сессии. Выход завершает сессию в текущем браузере.
- При истечении сессии показывается вход; приватные действия, включая отправку сообщений, недоступны.
- Поиск username по подстроке без учёта регистра. Текущий пользователь исключён из списка; email других пользователей не раскрывается.
- Пустой поисковый запрос показывает остальных пользователей, отсутствие совпадений — пустое состояние.
- При открытии диалога загружаются последние 50 сообщений. Более старые доступны через «Load more».
- Сообщения отображаются от старых к новым.
- Текст сообщения содержит 1–2000 символов после удаления пробелов по краям; пустые сообщения запрещены, переносы строк сохраняются.
- После восстановления соединения автоматически загружаются пропущенные сообщения; отображается состояние соединения.
- При неопределённом результате отправки приложение не сообщает об успехе. Повторная попытка одной отправки не создаёт дубликат сообщения.
- Автоматическая отправка новых сообщений во время офлайна исключена.
- Stories: запись с камеры, предварительный просмотр, публикация, возможность переснять до публикации.
- Запись автоматически останавливается на 15 секундах.
- Stories доступны всем авторизованным пользователям. Один автор может иметь несколько активных stories; внутри автора они просматриваются от старых к новым.
- Через 24 часа после публикации история недоступна, видео удаляется автоматически.
- Загрузка готовых видео, ручное удаление stories, счётчики просмотров и реакции исключены.
- Отказ в доступе к камере и неподдерживаемый браузер сопровождаются понятной ошибкой.

## Согласовано — раунд 3

- “Start conversation” сразу создаёт диалог и показывает его обоим участникам, даже до первого сообщения; подпись — “No messages”.
- Список диалогов показывает username собеседника, последнее сообщение и время.
- Список сортируется по последнему сообщению; для пустого диалога используется время создания.
- Новые диалоги и сообщения обновляют список без перезагрузки во всех открытых вкладках участников. Счётчики непрочитанных исключены.
- Stories записываются со звуком; при недоступном микрофоне разрешена запись без звука с уведомлением пользователя.
- Просмотр stories запускается пользователем. Для навигации достаточно «Previous» и «Next», автоматическое переключение не требуется.
- Через 24 часа story недоступна для просмотра независимо от работы фоновой очистки.
- При работающем сервере фоновая очистка удаляет файл и запись в БД в течение 5 минут после истечения срока. При запуске после простоя сервер очищает просроченное.
- Полный сценарий, включая запись stories, проверяется в актуальном Chrome на компьютере.
- Интерфейс дополнительно проверяется на узкой ширине экрана. Полная совместимость записи с Safari, Firefox и мобильными браузерами исключена из объёма.

## Согласовано — раунд 4

- UI: Flowbite Svelte; Tailwind согласно требованиям выбранного набора компонентов.
- Backend тестируется через публичные HTTP API и Socket.io с настоящей MongoDB в Testcontainers.
- HTTP-проверки: регистрация, вход/выход, ограничения доступа, поиск, история, повторная отправка без дубликатов, публикация и истечение stories.
- Socket.io-проверки: авторизация соединения, доставка событий участникам и отсутствие доставки посторонним.
- Backend-тесты не проверяют камеру и интерфейс; эти сценарии проверяются вручную в Chrome. Полноценные браузерные автотесты исключены из объёма.
- Сообщения отправляются через REST. После сохранения сервер доставляет новые сообщения и события создания диалогов через Socket.io во все вкладки участников.
- Повторная отправка использует тот же идентификатор попытки. После переподключения клиент сверяет состояние с сервером через REST.
- JWT хранится в HttpOnly cookie и действует 24 часа без автоматического продления. Первоначальное требование серверного отзыва при выходе заменено stateless-подходом в техническом уточнении ниже.
- Выход и истечение сессии прекращают доступ через Socket.io. Все вкладки текущей сессии теряют доступ; вход в другом браузере сохраняется.
- Пароли хранятся в виде стойкого хеша.
- Username: 3–30 символов, латинские буквы, цифры и `_`. Пароль: 4–128 символов, без обязательных требований к составу. Email обязателен, проверяется его формат.
- После регистрации пользователь сразу входит в приложение.
- Docker Compose входит в способ запуска приложения. Структура репозитория и хранилище видео согласованы в раунде 5.

## Согласовано — раунд 5

- Видео хранится на диске backend в Docker volume. MinIO не используется.
- Метаданные stories хранятся в MongoDB. Видео выдаётся через приватный API с проверкой сессии и срока действия story.
- Лимит загрузки видео: 25 МБ. Конвертация видео не выполняется; запись использует поддерживаемый браузером формат.
- Данные MongoDB и опубликованные видео сохраняются при перезапуске контейнеров.
- Репозиторий организован как pnpm workspace: `apps/web` (SvelteKit), `apps/api` (NestJS), единый lockfile.
- Общие пакеты создаются при конкретной необходимости.
- В корне располагаются команды разработки, проверок и тестов, `compose.yaml` и `.env.example`.
- Compose запускает всё приложение. Пользователь открывает один адрес на localhost; HTTP API и Socket.io доступны через тот же адрес.
- README описывает запуск через Compose и режим разработки. Облачные сервисы не требуются.
- Общая предметная область использует один корневой `GLOSSARY.md` и `docs/adr/`.
- Frontend использует Svelte stores для auth, messages и conversations согласно исходному заданию.

## Согласовано — раунд 6

- Целевой бюджет — 12 часов; допустимо небольшое превышение. Приоритеты сохраняются: рабочий чат, Compose, тесты и README, затем stories.
- Списки пользователей и диалогов используют infinite scroll вместо кнопки «Load more», порциями по 50.
- Пользователи сортируются по username; поиск выполняется по всем пользователям на сервере.
- Диалоги сортируются по последней активности; события обновляют список без дубликатов.
- Для истории сообщений остаётся ранее согласованная кнопка «Load more»; замена относится к спискам пользователей и диалогов.
- Мгновенное появление чужих stories через Socket.io не требуется.
- Просроченная история исчезает из открытой ленты. При истечении срока открытой истории воспроизведение прекращается и показывается «This story has expired».

## Согласовано — итоговое обсуждение

- Отдельной кнопки обновления stories нет. Лента обновляется при открытии, возвращении на вкладку браузера и после собственной публикации.
- Если пользователь остаётся на вкладке, чужая новая история появится при следующем открытии ленты или возвращении на вкладку; периодический опрос и real-time события stories не требуются.
- Лента показывает авторов активных stories; выбор автора открывает просмотр с кнопками «Previous» и «Next».
- Пользователь подтвердил общий объём и обновление ленты без отдельной кнопки.
- Просмотр stories меняет персональное состояние ленты: просмотренные истории визуально отличаются, полностью просмотренные авторы перемещаются в конец списка для текущего пользователя.
- Персональное состояние просмотра не добавляет счётчиков просмотров или списка зрителей для автора; они остаются вне объёма.

## Согласовано — персональный просмотр stories

- Состояние просмотра хранится отдельно для каждой пары «зритель — история», в MongoDB; сохраняется после перезагрузки и повторного входа.
- Автор считается полностью просмотренным, когда текущий пользователь просмотрел все его активные истории. Новая непросмотренная история возвращает автора в группу непросмотренных.
- Непросмотренные авторы идут перед полностью просмотренными. Внутри групп сортировка по времени последней активной публикации, от новых к старым.
- Просмотренные истории можно открывать повторно до истечения 24 часов; отметка просмотра не удаляет историю.
- История считается просмотренной после фактического начала воспроизведения, а не после простого открытия просмотрщика. Неудачная загрузка не отмечает просмотр.
- Перемещение автора выполняется после закрытия просмотрщика, чтобы порядок не менялся во время навигации.
- Непросмотренные авторы выделяются обводкой; после просмотра всех активных историй обводка меняется.

## Итог

### Уточнение авторизации после технического обсуждения

- Выбран stateless JWT без коллекции Session и без серверного списка отозванных токенов.
- Guard проверяет подпись и срок токена без запроса в хранилище сессий.
- Выход удаляет cookie, очищает состояние всех вкладок текущего браузера и отключает соединения текущего входа. Независимый вход другого браузера сохраняется.
- Копия JWT после выхода остаётся действительной до истечения срока, в том числе для нового Socket.io-подключения. Это заменяет первоначальное требование немедленного серверного отзыва.
- При истечении JWT HTTP-доступ прекращается, действующие Socket.io-соединения отключаются; показывается вход.

### Уточнение языка кода и приложения

- Все комментарии в существующем и новом коде, включая JSDoc/TSDoc, весь текст UI и все сообщения об ошибках пишутся на английском. Это включает ошибки валидации, HTTP API, Socket.io и внутренние ошибки приложения.
- Пользовательский контент сохраняется на языке пользователя; документация проекта может оставаться на русском. Это уточнение заменяет первоначальное требование русского UI.

### Состояние обсуждения

- Подтверждено техническое уточнение аутентификации: максимально использовать `@nestjs/passport`, `passport-local`, `passport-jwt` и guards на основе `AuthGuard`; выпускать JWT через `@nestjs/jwt`. Собственный код ограничить прикладной логикой и необходимой интеграцией без дублирования библиотечных механизмов. Приведение существующей JWT-защиты к этому подходу включено в задачу 02; согласованный жизненный цикл JWT сохраняется.

- Общее понимание требований и правила персонального просмотра stories подтверждены пользователем.
- Открытых вопросов по функциональному объёму и согласованному поведению нет.
- Техническое уточнение завершено, спецификация обновлена и итог подтверждён пользователем. Принята декомпозиция из девяти задач с критериями, дополненными техническими решениями.
