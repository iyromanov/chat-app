# 03: Загрузка переписки и простое обновление после reconnect

**What to build:** пользователь открывает диалог, читает последние сообщения и подгружает старую историю. После reconnect или возвращения на вкладку видит актуальные первые страницы истории и списка диалогов без восстановления всего прежнего диапазона.

**Blocked by:** [02 — Простая отправка и получение сообщений без attemptId](02-simple-message-send.md): продолжается перенос сценариев в подготовленный ChatController и используется общий обработчик сообщения.

**Status:** ready-for-agent

**Spec:** [Простая архитектура состояния и бизнес-логики чата](../spec.md).

## Границы работы

Перенести выбор диалога, HTTP-загрузку, пагинацию и обновление истории/диалогов в ChatController. MessagesStore и ConversationsStore содержат только реактивные данные, простые вычисления и синхронные изменения собственных данных. Корень связывает транспортные события и события жизненного цикла с контроллерами.

Реализовать объём обновления из [ADR 0008](../../../docs/adr/0008-simple-message-delivery.md): последние 50 сообщений активного диалога и первая страница диалогов. Удалить обход пропущенных страниц и прежнего загруженного диапазона. Более старые данные остаются доступны через существующие cursor, Load more и infinite scroll.

Не вводить кэш нескольких историй, новые API, event bus или общий framework отмены/ошибок. Сохранить полезную логику сортировки и объединения сообщений. Следовать [ADR 0010](../../../docs/adr/0010-client-state-and-controllers.md).

## Acceptance criteria

- [ ] Выбор диалога очищает предыдущую историю и загружает последние 50 сообщений. Пустая история, loading и ошибка различаются; ошибка допускает повтор загрузки.
- [ ] История хранится только для активного диалога, без отдельной копии активных сообщений или кэша других диалогов. Выбор остаётся локальным состоянием страницы.
- [ ] Load more подгружает старые сообщения существующим cursor; infinite scroll подгружает следующие страницы диалогов. Сортировка сообщений `(createdAt, id)` и диалогов по активности сохраняется.
- [ ] Reconnect и возвращение на вкладку обновляют последние 50 сообщений и первую страницу диалогов, сбрасывая старые курсоры/диапазоны. Автоматического обхода всего пропуска нет.
- [ ] После обновления Load more и infinite scroll используют новые курсоры и продолжают работать без дублей.
- [ ] События во время запроса объединяются с HTTP-ответом по серверным ID. Более свежее сообщение или превью не затирается устаревшим ответом; старый загруженный диапазон не сохраняется как кэш.
- [ ] События других диалогов меняют соответствующие превью, сохраняя открытую историю. Неизвестный диалог синхронизируется через ChatController, а не запросом внутри store.
- [ ] Быстрое переключение, logout, dispose и новый вход делают старые ответы неактуальными. Ошибка фонового обновления сохраняет отображаемые данные и вход, показывается пользователю и допускает повтор.
- [ ] Оба stores используют Svelte 5 runes, имеют readonly контракт чтения и явные синхронные методы изменения. HTTP, управление socket и обращения stores друг к другу отсутствуют.
- [ ] UI получает данные и actions через props, не изменяет доменные данные напрямую и не синхронизирует их через `$effect`. DOM-эффекты для прокрутки сохраняются; импорты соответствуют FSD.
- [ ] Проверки полного восстановления пропуска заменены проверками первых страниц и сброса курсоров. Сохранены интеграционные проверки событий во время загрузки, устаревших ответов и отсутствия дублирующихся обработчиков.
- [ ] Документация соответствует новому поведению; `pnpm check`, `pnpm test` и `pnpm build` проходят. Backend-интеграционные тесты выполняются с Docker/Testcontainers.
