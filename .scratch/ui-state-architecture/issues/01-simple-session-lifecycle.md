# 01: Простая авторизация и жизненный цикл приложения

**What to build:** пользователь регистрируется, входит, восстанавливает вход после перезагрузки и выходит через единый сценарий авторизации. Приложение опирается на ответы сервера и освобождает данные и соединение завершённого входа.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

**Spec:** [Простая архитектура состояния и бизнес-логики чата](../spec.md).

## Границы работы

Разделить AuthStore и SessionController, подключить их к одному корню приложения. AuthStore содержит реактивное состояние и синхронные переходы; SessionController выполняет запросы и координирует вход. Формы получают данные и actions через props, сохраняя локальные loading/error и поля ввода.

Сохранить авторизованный контекст на каждый успешный вход согласно [ADR 0007](../../../docs/adr/0007-authenticated-client-context.md). Контекст создаёт собственные HTTP-клиент, chat/stores и socket; старые операции не влияют на новый вход. В этой задаче существующие сценарии чата продолжают работать; их перенос в ChatController выполняется следующими тикетами.

Убрать клиентский таймер истечения JWT и localStorage-рассылку logout согласно [ADR 0009](../../../docs/adr/0009-server-driven-client-auth.md). Серверная проверка JWT, HttpOnly cookie и отключение истёкших сокетов сохраняются. Новые библиотеки и изменения оформления не требуются.

## Acceptance criteria

- [ ] Начальная проверка `/me` различает успешный вход, 401 и сетевую/серверную ошибку. Ошибку проверки можно повторить; сетевой сбой не объявляет пользователя гостем.
- [ ] Login/register проходят через SessionController. Пользователь берётся из существующего успешного ответа без обязательного дополнительного `/me`.
- [ ] Успешный вход создаёт ровно один авторизованный контекст; обычная перепроверка и reconnect сохраняют его. Пользовательское состояние не является серверным singleton.
- [ ] Успешный logout, актуальный 401 и `auth:ended` очищают данные и отключают socket. Ошибка серверного logout отображается и сохраняет вход; 401 означает, что вход уже недействителен.
- [ ] Поздние ответы восстановления, logout или 401 старого контекста не завершают и не перезаписывают новый вход.
- [ ] При ошибке подключения socket выполняется перепроверка `/me`; сетевой сбой не вызывает logout.
- [ ] Клиентский таймер JWT и localStorage-рассылка logout удалены. Отключённая вкладка может узнать о завершении входа при следующем обращении к серверу; эта задержка допускается.
- [ ] Socket создаётся после подтверждения авторизации. Повторное монтирование не добавляет соединения/обработчики; dispose освобождает ресурсы и инвалидирует старые операции.
- [ ] AuthStore не выполняет HTTP; формы не выполняют auth-запросы напрямую и не изменяют доменное состояние через публичные ссылки. Зависимости явные, импорты соответствуют FSD.
- [ ] Существующий обмен сообщениями остаётся работоспособным. Проверки композиции покрывают вход, ошибки, logout, устаревшие ответы и освобождение ресурсов; проверки клиентского таймера/рассылки заменены новым поведением.
- [ ] Документация соответствует новому поведению; `pnpm check`, `pnpm test` и `pnpm build` проходят. Backend-интеграционные тесты выполняются с Docker/Testcontainers.
