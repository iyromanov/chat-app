# Редизайн интерфейса чата

**Status:** ready-for-agent

## Согласованные границы

- Референс — композиция и компактность WhatsApp Web с существующей синей палитрой приложения. Точные размеры и второстепенные детали допускают уточнение.
- Desktop занимает viewport: постоянный Sidebar шириной 320 px и область выбранного диалога на оставшейся ширине. Список диалогов и сообщения прокручиваются независимо; верхние блоки Sidebar остаются на месте.
- Mobile показывает один полноценный экран: список диалогов, поиск либо переписку. Возврат из переписки ведёт в исходный экран.
- Область редизайна — авторизованная часть. Вход и регистрация не входят. Внешний вид ленты видеоисторий, записи и просмотра согласуется в рамках дизайна; работающая функция реализуется отдельно, и блок появляется в приложении вместе с ней.
- Сохраняются текущие API и поведение реализованных функций, включая восстановление связи и повтор отправки.
- Аватар пользователя — круг с первыми двумя символами username, с сохранением регистра. Если символ один, показывается он; символы считаются по Unicode code points. Online-статус, счётчики непрочитанных и другие отсутствующие в текущих контрактах возможности не добавляются.
- Интерфейс остаётся англоязычным согласно CODING_STANDARDS.md.
- Синяя палитра используется для акцентов, выбранного диалога, исходящих сообщений и непросмотренных историй.
- Первая версия редизайна имеет только светлую тему: белый Sidebar, светлый нейтральный фон переписки, белые входящие и светло-синие исходящие сообщения. Тёмная тема — отдельная задача.
- Flowbite остаётся основой UI; допускается настройка цветов, размеров, скруглений и состояний компонентов.
- Desktop: фокус в поиске переключает список диалогов на пользователей; пустой запрос показывает остальных пользователей. Escape или кнопка закрытия возвращает список диалогов. Stories сохраняют положение после появления этой функции.
- Mobile: поиск открывается отдельным экраном, включая список пользователей при пустом запросе. Возврат из переписки, открытой через поиск, сохраняет запрос и результаты.
- При ширине viewport от 768 px используется desktop; ниже — mobile. При смене режима выбранный диалог сохраняется; на mobile открытый диалог занимает экран.
- При открытии диалога показываются последние сообщения. Входящие автоматически прокручивают вниз только пользователя, который уже находится внизу; при чтении старых сообщений позиция сохраняется и появляется кнопка перехода к новым. Собственная отправка переводит вниз. Подгрузка старых сообщений сохраняет положение.
- Черновики сохраняются отдельно для каждого диалога при переключениях, до перезагрузки страницы; выход очищает их. Возврат к списку диалогов или поиску сохраняет прокрутку соответствующего списка.

## Композиция и критерии приёмки

### Desktop

- Приложение занимает доступные высоту и ширину viewport, без карточки приветствия, ограничения общей ширины и прокрутки всей страницы.
- Sidebar шириной 320 px остаётся видимым при открытии диалога. Сверху вниз: заголовок приложения с выходом, поиск с горизонтальными отступами 12–16 px, место ленты Stories после реализации функции, затем список Chats либо результаты поиска.
- Заголовок Sidebar ориентировочно 56 px. Верхние блоки не прокручиваются вместе со списком. Список занимает оставшуюся высоту и имеет собственную вертикальную прокрутку.
- Строка диалога содержит аватар с инициалами, username, превью последнего сообщения и время. Для пустого диалога сохраняется подпись `No messages`. Выбранный диалог выделяется светло-синим фоном.
- Правая область занимает всю оставшуюся ширину. Она не зависит от прокрутки Sidebar.
- Без выбранного диалога по центру показываются минималистичная иконка сообщений, `Select a chat` и `Or find a user using search`; заголовок переписки и composer скрыты.

### Переписка

- Заголовок высотой ориентировочно 60 px содержит аватар с инициалами и username. На mobile слева есть кнопка возврата. Кнопок звонков и дополнительных инструментов нет.
- История сообщений занимает свободную высоту и прокручивается независимо. Входящие слева на белом фоне, исходящие справа на светло-синем. Пузыри содержат текст и время отправки; переносы и длинные непрерывные строки не ломают раскладку.
- Composer находится в нижней области переписки: растущее многострочное поле и кнопка отправки справа. Enter отправляет, Shift+Enter добавляет перенос строки. Кнопок вложений, микрофона и эмодзи нет.
- Ошибки загрузки и отправки, повтор отправки и состояние восстановления связи сохраняют существующее функциональное поведение и вписываются в новую раскладку.

### Mobile и поиск

- На стартовом экране заголовок `Chats`, иконка поиска и компактное меню с действием `Sign out`. Выход не требует экрана настроек.
- Список диалогов занимает оставшуюся высоту; заголовок и будущая лента Stories остаются на месте при прокрутке.
- Поиск имеет кнопку возврата, поле и список пользователей. Строка пользователя содержит аватар с инициалами, username и действие начала переписки. Технический id не выводится как отдельное имя или публичный идентификатор.
- Выбор пользователя открывает единственный существующий диалог либо создаёт его согласно текущему API. Открытие переписки из поиска сохраняет точку возврата; из списка — возвращает в список.
- Поиск различает пустой запрос со списком пользователей, загрузку, найденные результаты, отсутствие результатов и ошибку с повтором. Подгрузка пользователей и диалогов сохраняется.
- Переписка занимает весь доступный viewport. При открытии экранной клавиатуры composer остаётся доступным, область сообщений изменяет высоту; учитываются безопасные отступы устройства.

### Внешний вид видеоисторий для отдельной реализации

- Stories располагается между поиском/заголовком и списком диалогов. Лента горизонтальная, с круглыми аватарами и username под ними; первый элемент — добавление собственной видеоистории с иконкой `+`.
- Непросмотренные авторы выделены синей обводкой; полностью просмотренные отличаются нейтральной обводкой. Порядок авторов и персональное состояние просмотра следуют исходной спецификации и глоссарию.
- Запись, предварительный просмотр, пересъёмка и публикация оформляются компактным модальным окном на desktop и полноэкранной областью на mobile. Просмотр видео следует тому же принципу, с закрытием и ручными переходами Previous/Next.
- Ограничение 15 секунд, срок жизни 24 часа и состояния доступа к камере, публикации и истечения срока наследуются из исходной спецификации. Автоматическое переключение историй не добавляется.
- Эти композиции не требуют сейчас фиктивных пользователей, неработающих кнопок или пустого блока Stories в рабочем приложении. Реализация видеоисторий не является критерием завершения редизайна чата.

## Проверка

- Проверить desktop с пустой правой областью и открытым диалогом; независимую прокрутку длинных списков и истории, поиск и его закрытие.
- Проверить mobile: список → диалог → возврат, поиск → диалог → возврат с сохранённым запросом, меню выхода, клавиатуру и длинный текст.
- Проверить смену ширины через 768 px с выбранным диалогом, черновики разных диалогов, входящие при чтении старой истории и подгрузку без скачка позиции.
- Проверить существующие сценарии отправки, ошибок, повтора и восстановления связи; выполнить применимые проверки форматирования, типов и импортов проекта.
- Вход и регистрация сохраняют существующее оформление и поведение.

## Факты, требующие уточнения объёма

- Видеоистории описаны в исходной спецификации и GLOSSARY.md, но пока не реализованы: отсутствуют контракты, API и UI. Работающие создание и просмотр требуют самостоятельной функциональной реализации, а не только редизайна.
- Пустой поисковый запрос по текущей спецификации показывает остальных пользователей.
- Ограничения оформления в ADR 0006 и CODING_STANDARDS.md уточнены по результатам второго раунда: библиотека сохраняется, визуальная настройка разрешена.
