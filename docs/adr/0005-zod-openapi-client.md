# Zod-контракты и типизированный HTTP-клиент из OpenAPI

Используем общий framework-независимый пакет Zod-контрактов, DTO через nestjs-zod и OpenAPI через @nestjs/swagger. Из OpenAPI `swagger-typescript-api` генерирует HTTP-типы и Fetch-клиент в `generated.ts`. Прикладной код вызывает методы, сгруппированные по первому тегу OpenAPI (`api.auth.register`, `api.messages.send`); имя метода получается из `operationId` без префикса контроллера через hook библиотеки; URL, HTTP-методы и сериализация остаются внутри генерируемого клиента. Библиотека заменяет `openapi-typescript`, `openapi-fetch` и собственный генератор обёртки операций: принимаем стандартные сигнатуры и шаблоны библиотеки, чтобы не поддерживать генерацию вручную. Фабрика shared настраивает cookies и обработку HTTP-ошибок через `customFetch`, сохраняя `ApiError` и callback потери авторизации. Это заменяет вручную поддерживаемые HTTP-типы клиента; описание маршрутов, статусов и авторизации остаётся в контроллерах, поля DTO выводятся из Zod.

Общий пакет сохраняется для форм, серверной валидации и Socket.io-событий, которые HTTP-генерация не покрывает. Генерируемые TypeScript-типы не являются runtime-валидатором ответов. Клиент создаётся фабрикой shared для экземпляра приложения; app связывает ошибки авторизации с состоянием входа. Цена решения — первоначальная настройка и поддержка команд экспорта OpenAPI, генерации и проверки актуальности артефактов.
