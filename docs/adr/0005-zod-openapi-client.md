# Zod-контракты и типизированный HTTP-клиент из OpenAPI

Используем общий framework-независимый пакет Zod-контрактов, DTO через nestjs-zod и OpenAPI через @nestjs/swagger. Из OpenAPI openapi-typescript генерирует HTTP-типы, а openapi-fetch выполняет типизированные запросы. Дополнительно из `operationId` генерируется `operations.ts`: прикладной код вызывает именованные методы, а URL и HTTP-методы остаются внутри генерируемого клиента. Небольшой генератор связывает операции с типизированными методами openapi-fetch без отдельного транспортного слоя; его поддержка входит в стоимость решения. Это заменяет вручную поддерживаемые HTTP-типы клиента; описание маршрутов, статусов и авторизации остаётся в контроллерах, поля DTO выводятся из Zod.

Общий пакет сохраняется для форм, серверной валидации и Socket.io-событий, которые HTTP-генерация не покрывает. Генерируемые TypeScript-типы не являются runtime-валидатором ответов. Клиент создаётся фабрикой shared для экземпляра приложения; app связывает ошибки авторизации с состоянием входа. Цена решения — первоначальная настройка и поддержка команд экспорта OpenAPI, генерации и проверки актуальности артефактов.
