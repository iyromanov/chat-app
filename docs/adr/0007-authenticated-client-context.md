# Клиентский контекст на каждый успешный вход

Аутентификация, жизненный цикл Socket.io и оркестрация stores разделены на внутренние модули слоя app. Композиция приложения связывает их явно; транспорт не знает о предметных stores, а entity-срезы не импортируют друг друга.

Каждый успешный вход, включая восстановление аутентификации и повторный вход того же пользователя, создаёт новый контекст: HTTP-клиент, stores сообщений и диалогов, Socket.io-соединение. При завершении входа старое соединение отключается, stores очищаются, незавершённые загрузки инвалидируются. Поздний ответ HTTP с 401 из прежнего контекста не завершает новый вход. Обычная повторная проверка аутентификации и переподключение сохраняют текущий контекст.

Выбрали отдельные экземпляры вместо повторного использования и сброса stores: принадлежность данных и обработчиков конкретному входу становится явной. Цена — пересоздание контекста и экрана чата при каждом успешном входе. Проверки устаревших операций сохраняются: новая композиция сама по себе не отменяет уже отправленные HTTP-запросы и не управляет применением cookie браузером.

[ADR 0011](0011-client-without-generation-counters.md) отменяет проверки поколений параллельных операций авторизации. Защита уничтоженного контекста и пагинации сохраняется.
