# FSD и клиентская загрузка приватной области

Frontend организован по FSD с публичными интерфейсами срезов и зависимостями от верхних слоёв к нижним; маршрутизация SvelteKit адаптируется к слою app. Это делает правила размещения логики и импортов едиными для реализации задач, ценой адаптации стандартной структуры SvelteKit; слои создаются по необходимости.

Данные приватного чата загружаются в браузере из NestJS API после проверки сессии, Socket.io также подключается только в браузере. Выбрали это вместо SSR переписки, чтобы один клиентский поток управлял загрузкой истории и событиями; до проверки сессии показывается загрузка, а реальный доступ к данным контролирует backend. Пользовательские stores не размещаются в общем серверном состоянии.
