# Простая отправка и обновление истории для тестового чата

Для масштаба тестового задания отказываемся от `attemptId` и идемпотентного повтора отправки: обычный POST с текстом создаёт сообщение, UI блокирует отправку на время запроса, очищает текст после успеха и сохраняет его при ошибке. Отдельной неопределённой попытки, специального Retry и автоматических повторов нет. Это упрощает клиентскую модель, API и хранение ценой возможного второго сообщения при повторной отправке после потери ответа; одинаковый текст сам по себе не считается дублем.

После переподключения и возвращения на вкладку клиент загружает последние 50 сообщений активного диалога и сбрасывает его старую пагинацию. Список диалогов также обновляется с первой страницы и сбрасывает прежнюю пагинацию; остальные страницы доступны через infinite scroll. Более ранняя история остаётся в MongoDB и доступна через Load more; автоматического обхода всех пропущенных страниц и восстановления прежнего загруженного диапазона нет. Сохраняются объединение HTTP/WS по серверному Message ID, учёт событий во время запроса и защита от устаревших ответов.

Решение заменяет требования безопасного повтора и полного автоматического восстановления пропуска из прежней спецификации и задачи 05. [ADR 0004](0004-message-source-of-truth.md) сохраняет силу в части MongoDB как источника истины, REST-синхронизации и уведомлений после сохранения; объём синхронизации ограничен этим решением. Изменение согласовано на стадии проектирования; реализация ещё не выполнена.
