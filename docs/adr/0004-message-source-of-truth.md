# Сообщения как источник активности диалога и восстановления

Последнее сообщение и активность диалога вычисляются из Message при запросе списка, а не дублируются в Conversation. Выбрали более сложный индексированный запрос для масштаба тестового вместо согласованного обновления нескольких документов и инфраструктуры транзакций.

Socket.io рассылает уведомления после сохранения сообщений; надёжное восстановление выполняется из MongoDB через REST при начальной загрузке, переподключении и возвращении на вкладку. Transactional outbox и долговечная очередь не используются: сбой между сохранением и рассылкой может задержать отображение до следующей синхронизации, но сохранённые данные не теряются. Клиент объединяет REST-данные и события по идентификаторам, включая события во время загрузки.
