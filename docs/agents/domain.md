# Domain docs

This repository uses a single domain context.

Before exploring, read `GLOSSARY.md` and relevant ADRs
under `docs/adr/`, when present.
If absent, proceed silently.

Use glossary terms consistently in specs, tickets, and code.
Surface conflicts with existing ADRs explicitly.

Create the glossary when the first term is resolved.
Create ADRs for decisions involving a meaningful trade-off,
costly reversal, and rationale a future reader will need.
Keep implementation details out of the glossary.
